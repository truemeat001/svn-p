# 文件操作与仓库锁 GUI

这些功能使用真实 Tkinter 对话框与独立后端，不是截图或网页演示。操作范围始终限制在当前打开的一个实际 SVN 工作副本中。

## 从哪里操作

- 在“工作副本文件”页选择具体文件，右键可移动/重命名、保留历史复制、删除或检查仓库锁。
- 在“待提交更改”页选中受支持的文件行，也有相同右键菜单。干净文件不一定出现在此页，可到“工作副本文件”中选择。
- 顶部“文件与锁”菜单提供相同入口；“仓库锁…”工具条按钮针对当前文件选区。
- 左侧导航目录、分组标题、仓库浏览结果不会自动成为操作目标。混合选中目录或组不会被悄悄跳过。没有选择时不会解释成整个工作副本。
- 菜单的可用状态来自最近一次读取的本地状态，只是提示。执行前始终重新进行后端预检，不能当作状态保证。

## 本地删除、移动、复制

1. 删除可选择最多 128 个内容及属性均未修改的普通已版本化文件；移动/复制一次只选择一个文件。
2. 移动/复制先输入工作副本内的确切相对目标路径。必须包含新文件名，目标不能已存在，目标父目录必须已存在且已版本化。不会自动创建父目录、覆盖、移入整个目录、跨副本或猜测大小写重命名。
3. 后台预检读取全部源、目标和祖先状态，以及内容/属性指纹。确认页显示整个工作副本路径、全部受影响文件、源/目标关系和风险。没有自动执行或默认回车确认。
4. 勾选已核对风险后明确确认，才会将预检指纹交给后端复核并执行。预检返回和确认后都会核对当前工作区、页签与选区；发现不一致时取消旧计划。
5. 成功只表示本地 SVN 计划变更及目标检查完成，没有提交服务器。应继续审查状态和内容后另行提交。

删除会移除当前本地文件并安排后续仓库删除，务必保留独立备份。移动/复制支持受限普通文件的本地内容/属性修改，并保留 SVN 复制历史。移动两端需一起审查提交，不会为你自动补齐范围。变更列表标签不保证自动转移。

目录、URL、链接/junction、嵌套工作副本、外部引用、冲突、switched 和已有新增/删除/替换/复制/移动等结构状态不支持。范围和实现限制见 [文件操作后端说明](FILEOPS.md)。

## 仓库文件锁

1. 选择最多 128 个已提交的普通文件，点击“仓库锁…”或右键检查。检查是只读的，但逐文件访问仓库服务器，可能耗时。
2. 查看每个文件的服务器锁、所有者、备注和本工作副本是否真正持有该锁。界面不显示或保存原始锁令牌。
3. 明确选择加锁或解锁，没有默认选项。加锁备注可选，备注会发送仓库服务器并可能被团队看到，请勿填凭据或秘密。
4. 只能申请未锁定且不落后于服务器的文件；只能释放本工作副本持有的当前锁。同用户名在另一工作副本中的锁也不能释放。没有抢锁、破锁、`force` 或自动重试。
5. 新的预检读取服务器状态，最终确认完整文件、归属、备注和风险后才能执行。成功后会再次读取服务器状态验证，而不是仅凭进程退出码。

锁会影响他人提交，但不能阻止其他人在本地编辑。`svn:needs-lock` 可能改变本地文件可写权限。成功提交通常会释放 SVN 收集到的锁，本工具不改变此默认行为。

文件内容/属性修改可以与文件锁操作并存，但目录、结构变更、冲突、外部引用、链接/junction、硬链接等不支持。完整限制及认证范围见 [仓库文件锁说明](LOCKS.md)。

## 失败与边界

- 预检不是事务或排他锁。执行期间不要在外部编辑器或其他 SVN 客户端中并行修改相关内容。
- 预检/执行前复核拒绝会明确指出未发出修改命令；命令失败、超时、部分成功或后续验证失败都可能已有实际结果。
- 程序不会自动回滚或重试。它会展示原工作副本和确切目标，刷新当前仍是同一副本时的本地状态；锁操作尽可能附上后读的服务器状态。先核查，再决定新的操作。
- 旧工作副本或旧选区的结果不会覆盖新选区详情，也不会刷新另一个工作副本。
- 演示模式不打开真实操作流程，也不运行文件或仓库锁写入。

本轮验证使用临时文件、模拟后端和无显示 GUI 回调/构造测试。未完成真实 SVN 服务、原生 Windows 窗口、网络认证、服务器 hook 或 125%–200% DPI 交互验收。
