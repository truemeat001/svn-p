# 本地工作区、启动恢复与多个 SVN 副本

## 打开一次，下次自动恢复

1. 点击“打开…”选择已有 SVN 工作副本。验证成功后，程序登记名称和工作副本根目录。
2. 下次正常启动自动恢复上次**成功打开**的工作区。命令行明确传入的路径优先。
3. 上方“工作区”下拉框可切换已登记副本。“管理…”可重命名、重新定位目录、移除记录，以及关闭自动恢复。

旧版已有的 `last_workspace` 路径会迁移成一条登记记录，不必重新建立仓库。此前代码只保存路径供文件选择框使用，现在启动时会实际读取并恢复。

记录保存在当前用户目录的 `.svn-desk/settings.json`，Windows 通常是 `%USERPROFILE%\.svn-desk\settings.json`。因此解压新版到其他位置，不会因程序目录改变而丢失登记。保存采用临时文件加原子替换，允许的字段只有工作区 ID、名称、本地路径、SVN 程序路径和启动偏好；不自动保存仓库 URL、密码或认证令牌。

设置写入在单个进程内串行化；多个程序实例同时修改登记不提供合并，最后一次保存生效。建议在同一个窗口内切换工作区。

路径失效、SVN 程序缺失或验证失败时，原记录保留，当前已打开的副本不会被替换。使用“重新定位目录”修复路径即可。原设置文件损坏时不会静默覆盖，重建前会明确询问。保存失败会提示，当前会话仍可继续，但不能保证下次恢复本次修改。

**移除记录不是删除工作副本。** 不会移动、删除或还原任何文件。即使移除当前记录，也可继续使用本次会话中已打开的副本；其后不会再按被移除的记录自动恢复。

演示模式不读取实际工作区设置，也不会保存设置、扫描目录或检出文件。

## 从仓库新建本地工作区

点击“新建 / 检出…”，填写名称、仓库 URL 和本地目录，先检查再确认下载。

- 支持 `http`、`https`、`svn` 和 `file` 仓库 URL。内置流程不支持 `svn+ssh`，因为外部 SSH 工具可能交互等待或超出 SVN 超时范围；请先用可信 SVN/SSH 客户端检出，再登记已有副本。
- 目标只能是空目录，或父目录已存在的新目录。不能位于另一个工作副本内，不跟随符号链接或重解析点，不使用强制覆盖。
- URL 不能包含密码、查询参数或片段。用户名可按服务要求出现在 URL 中，但 URL 不写入工作区登记。
- URL 保留 SVN 的 `@修订` 语法。没有指定时通常使用 HEAD；例如 `.../trunk@17` 会按指定修订检出。路径本身含字面 `@` 时，应按 SVN 语法在 URL 末尾附加空的 `@`，不要把文件名的一部分误当修订号。
- 使用安装的 SVN 客户端已配置的认证；不弹出密码输入、不保存新认证、不绕过证书检查。缺少认证时会失败并交由用户配置。
- 不自动检出 externals，不创建服务器仓库或 P4V 式服务器 workspace。
- 超时或失败可能留下部分工作副本，程序不会自动删除、重试或覆盖它。检查并修复目标目录后，再打开已有副本。

只有检出完成且随后验证成功，才登记并打开新工作区。

## 一个父目录下有多个仓库

在“管理…”中选择“扫描父目录…”。直接打开一个并非工作副本的父目录时，若 SVN 明确报告该状态，程序也会提供扫描入口。

扫描只查看目录名和文件系统元数据，寻找 `.svn` 标记。它不读取项目文件内容、不进入 `.svn` 内部、不跟随链接或重解析点，也不把父目录当作一个可提交的工作副本。

默认边界为深度 8、最多 10,000 个目录、50,000 个条目、200 个候选根和约 5 秒协作式时间限制。慢磁盘或网络文件系统调用可能超过这个时间，系统调用本身不能被 Python 强制中断。扫描在后台线程执行，截断和访问问题会显示，不能把部分结果当作完整清单。

结果中的每个候选均需单独通过 SVN info 验证：

- “打开一个选中项”只打开这一个工作副本。
- “验证并登记选中项”可登记多个已验证根，但不改变当前打开的副本，也不更改“上次成功打开”的记录。
- 无效候选单独报告，不阻止其他有效根登记。
- 切换工作区后，待提交选区和文件范围会重置。更新、提交、归组和 Shelf 操作始终针对当前选中的单个工作副本，不能跨根组合提交。

## Nested WC 与 externals 的边界

嵌套 `.svn` 可以作为另一个候选根被发现并单独登记，但“位于另一个副本下面”**不等于**已确认它是 `svn:externals`。

本版不自动导入外部引用定义、固定修订、父子依赖或远程仓库身份。目录 externals 可能作为候选出现；没有独立 `.svn` 根的文件 externals 不是独立工作区。检出和更新默认忽略 externals。若手动打开嵌套或外部副本，请先了解其外部引用和固定修订要求，再决定是否更新。

这仍是 SVN 的本地工作副本登记系统，不是 P4V 的服务器工作区规范、视图映射或多仓库事务管理。

## 验证状态

已覆盖设置迁移、原子写入、无删除移除、失效路径保留、启动竞争、明确输入优先、检出取消/失败、成功打开/重新定位，以及多个候选独立验证等单元和回调测试。实际 SVN 集成测试需要 `svn` 与 `svnadmin`；开发环境缺少这些程序时会跳过。原生 Windows 图形显示、真实认证、长时间网络和大仓库运行仍需在一次性工作副本中验证。
