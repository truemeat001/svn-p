# 冲突检查与手工解决 GUI

本界面对应 `svn_client/conflicts.py` 的保守解决流程，不是三方合并编辑器，也不自动修复冲突。

## 使用方法

1. 打开实际 SVN 工作副本根，刷新待提交列表。通过“冲突 → 筛选冲突”定位节点。
2. 在可信编辑器或 SVN 工具中检查并保存需要保留的当前文件。若为文本，需自行处理冲突标记；二进制文件也必须人工核对。
3. 选中确切的冲突文件行，通过工具栏、右键或“冲突 → 检查选中冲突”进入检查。组标题不是文件目标，混合选中普通文件会被拒绝，不会偷偷跳过。
4. 查看每个节点的状态和限制原因。界面没有默认解决选项。只有所有节点均符合范围时，才能明确选择“保留手工修复后的当前文件（working）”，并勾选人工检查确认。
5. 预检重新读取状态与内容指纹，显示精确的工作副本和全部目标。再次确认理解冲突辅助文件将被移除、已另行保护重要内容且不会并行编辑后，才能执行。
6. 执行后刷新状态。成功表示 SVN 命令及后续目标状态检查通过，不证明内容正确，也不会提交仓库。

## 支持与限制

- 只支持实际工作副本根内、已版本化普通文件的纯内容冲突，保留当前工作文件内容，使用 `working`。可以是文本或二进制文件。
- 单次最多 128 个节点；单个内容指纹文件最多 32 MiB。具体安全限制以后端检查为准。
- 属性、混合、树冲突，以及复制/移动、switched、外部引用、链接或不安全祖先节点等状态不在此流程内。`base`、`mine-full`、`theirs-full` 均不提供。
- 每个目标按 `depth=empty` 处理，不递归，不扩大到组或目录，也不跨工作副本。
- 指纹包含当前工作文件内容，但不包含冲突辅助文件的内容。SVN 可能移除这些辅助文件，即使它们另外被编辑过。因此必须先独立保护辅助文件中需要保留的内容。
- 指纹预检不是排他锁或事务。外部程序仍可能修改文件；不要并行编辑或运行其他 SVN 变更操作。
- Shelf 不是冲突备份替代方案：本工具的 Shelf 对不支持的冲突状态会拒绝，不能依赖它保存全部冲突辅助文件。
- 检查返回、预检返回及确认后都会核对工作副本、页签和文件选择；发现不一致时取消原操作。恢复时应重新选择、重新检查，不复用已取消的确认。
- 预检或 token 复核拒绝会明确提示没有执行解决命令；命令失败、超时或后续状态校验失败会提示可能已有部分结果，并刷新原工作副本。界面不会自动重试，应先人工核查。
- 演示模式不执行检查或解决真实工作副本。

## 验证范围

GUI 流程通过无显示环境下的回调、纯函数和静态事件绑定测试，覆盖取消、明确确认、unsupported 混选、工作区/选择变化、精确 token、失败处理和旧回调不覆盖新详情。未在 Windows 原生窗口或真实 SVN 冲突场景中运行验证，不能视为完整的交互验收。
