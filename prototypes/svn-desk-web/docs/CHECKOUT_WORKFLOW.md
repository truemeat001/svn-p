# 固定目标检出：实验性源码检查点

**Windows 安全复测未通过，暂不用于真实工程。** 202367d 的属性访问句柄不能阻止目录重命名，实际 SVN 在替换目录写入后才报不确定。本轮修正访问权限并增加真实临时仓库回归，修正版仍须对精确提交进行 Windows 重测；旧版本不能因常规检出通过而视为安全。见 [Windows 目录句柄修正](CHECKOUT_WINDOWS_GUARD_FIX.md)。

现代界面补上首次检出的工作流：启动时指定唯一仓库 URL 与新/空目录，打开「检出…」，做只读本地预检，再明确确认访问该仓库并写入该目录。成功后加入「工作副本」候选，用户自行选择并读取状态；不会自动切换现有工作区。

本轮只更新源码。已交付的旧 Windows / Electron 试用包不包含这项能力；本轮没有构建或交付新可执行包。

## 启动与范围

在可信完整源码目录中，用已安装的 SVN 启动，例如：

```powershell
python prototypes/svn-desk-web/server.py --backend-source "C:\Tools\svn-p" --checkout-url "https://svn.example.test/project/trunk" --checkout-destination "C:\Work\new-project"
```

示例地址不可作为实际仓库使用。请替换为自己有权限访问的仓库和专用新目录。父目录必须已存在，目标必须不存在或为空。启动本身不运行检出或远程预检；确认前不创建目标目录。

配套的 desktop_bridge.py、WinForms 参数转发、Electron 参数解析已接受这两个成对参数。冻结桥接构建清单同时包含 checkout_ops.py 与 checkout_paths.py。**当前 Electron build.py 仍是历史 5298602 桥接/静态资源的精确装配器，不接受本轮源码的新桥接，不得混装或宣称其产物具有检出。** 需另行更新包装契约、重新构建并完成 Windows 验收。WinForms 也必须重新构建配套桥接，不能只替换 HTML。

- 网页只得到固定 URL/目录；请求不能提供任意地址、路径、命令或凭据。
- 支持 http/https/svn 和本机 file URL；不支持 svn+ssh、远程 file 主机、URL 用户名/密码、查询/片段或显式 peg 修订。路径中的字面 `@` 需 URL 编码。
- 目标是绝对本地目录；Windows 只接受普通盘符路径，拒绝 UNC、盘符相对路径、ADS 和尾随点/空格别名。
- 目标与所有祖先不能是 symlink/junction/reparse point，不能位于已有 SVN 工作副本内，不能包含偏好文件。已有内容不覆盖；不创建缺失的上级目录。
- 不采集账号/密码，不写入新认证缓存。`--non-interactive --no-auth-cache` 仍可能使用用户已配置的 SVN 凭据缓存/认证提供程序；需要登录或证书处理时请用可信原客户端处理。本功能不管理凭据或绕过 TLS。

## 确认、执行和恢复

当前只检出执行时的 HEAD，没有指定修订功能；预检不访问仓库，也不会固定远程修订。仓库可在预检后前进，最终内容可能来自更新的 HEAD。

本地预检只验证目录身份，生成 120 秒、一次性的内存计划。取消、关闭、超时或新的预检会使旧计划失效。应用请求必须附确认值；目标被改变或令牌失效时拒绝。与同一桥接的其他工作区操作共用串行锁，多个标签页不能并行执行。

确认后只执行固定 `svn checkout --ignore-externals --quiet`，并用本地 `svn info --xml --depth empty .` 验证根目录与原 URL。每个命令 stdout 上限 256 KiB，stderr 上限 64 KiB，两步共享最多 300 秒预算（不包含不可取消的文件系统阻塞或有限进程清理时间）。零退出状态附带 stderr、非空 quiet 输出、无效/声明性 XML、URL 或根不匹配均不能宣称成功；URL 重定向/标准化差异也会保守地视为未核实。

一次尝试开始后，本会话不再允许第二次检出，包括超时、进程失败或核验失败。所有已创建内容保留，无强制覆盖、自动重试、删除、回滚或修复。关闭弹窗不等于取消，迟到结果仍留在主界面；HTTP 409 也可能意味着另一窗口已尝试，不能被解读为“完全没有写入”。先核对目录与正在运行的进程，再决定下一步。重新启动不能恢复或继续部分检出；非空目录会被拒绝。

## 路径保护与限制

Linux 创建新目录时锚定已打开的父目录，启动 SVN 时以已打开目录的 `/proc/<pid>/fd/<fd>` 为 cwd，避免名称被替换后把写入转向别的目录。Windows 在创建、执行、核验和注册期间以 FILE_LIST_DIRECTORY | FILE_READ_ATTRIBUTES（0x81）持有所有祖先及目标目录的 FILE_SHARE_READ 句柄。不能仅用属性访问（0x80）：Windows 实测该模式允许重命名。修正后不回退权限或扩大共享范围；实际共享排斥与 SVN 兼容性以修正版 Windows 重测为准。不支持所需锚定设施时，在 SVN 启动前失败关闭。

这不是文件系统事务或对恶意同用户进程的完整隔离。目录内部文件、仓库内容、外部程序和系统强制终止不受全局保护，不要并行修改目标或操作同一工作副本。Windows 原生句柄共享行为、与真实 SVN 对目录属性操作的兼容性仍须测试；修正前 Windows 常规真实流程 53/53 通过，但目录替换回归失败，因此不能宣称 Windows 检出已验收。修正版的 Linux/模拟测试也不能替代 Windows 对真实共享排斥和 SVN 兼容性的重测。

## 验证

- 包含固定请求、令牌/过期/重复确认、并发、URL/目录边界、输出/XML/根身份、局部失败保留、跨窗口结果、关闭/迟到响应测试。
- 使用自己的临时目录与真实 Python 子进程做管道测试；没有访问用户仓库、服务器或现有工程。Linux 进程启动瞬间替换目录与创建前替换父目录的回归证明没有在替代目录写入。
- Chromium 实机浏览器测试已编写，但当前环境因 socket 权限拒绝而无法启动，包括获审查的提权尝试；没有浏览器断言或截图验收结果。
- 当前环境未安装 svn/svnadmin，也不能运行 Windows C# 编译/原生 GUI。真实 SVN、Windows 目录句柄、冻结程序、完整交互与 DPI 均待对应平台验收。原有选测跳过与新增平台专用跳过不算通过。
