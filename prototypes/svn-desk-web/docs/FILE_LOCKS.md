# 现代 UI 仓库文件锁 / 解锁

本切片是集成开发分支 `069d454` 之后的 opt-in 功能。复用原版 `svn_client.locks.LockManager`，不替换旧应用、不改原锁核心、不提供 force、窃锁、破锁、令牌输入或 URL 写入接口。不是 Windows / 真实 SVN 验收通过，也不是可发布客户端。

## 启用与使用

```sh
python3 server.py --workspace "/path/to/disposable-test-wc" \
  --backend-source "/path/to/paired-original" --enable-locks
```

未显式启用时真实锁入口不可用，离线演示不模拟成功。配套 backend/history/locks 源码通过已审核版本指纹核对后才启用，CRLF 换行不会误伤。其他写能力仍分别启用。

1. 选择 1–100 个明确已提交普通文件。包含筛选/折叠隐藏的选中成员，不扩大为目录或整个 changelist，不跳过不合格文件。
2. 点击工具栏或文件菜单的「锁定明确选区」/「解锁明确选区」。打开窗口不查询服务器。
3. 加锁可填最多 4096 UTF-8 字节的说明。界面明确告知说明将随确认后的锁命令发送给仓库，可能被团队看到；不得包含凭据/令牌。
4. 单独点击预检：完整本地验证后，逐文件访问服务器核对当前锁与修订。预检不加锁/解锁，也不向仓库发送说明。
5. 完整预览通过后，另行确认执行。锁定只能取得当前未锁定且不落后的文件；解锁必须持有本工作副本匹配的当前令牌，同用户名的其他副本也不能破锁。

锁会影响他人的提交，不防止本地编辑；`svn:needs-lock` 可能改变所选文件的可写权限。多文件不是原子事务。请不要并行编辑这些文件或运行其他 SVN 工具。

## 范围、计划与安全边界

- 启用锁后刷新使用本地 `status(verbose=True)`，显示干净状态项以便选择未修改文件。不会加 `--show-updates`、自动访问仓库或把 `wc_locked` 管理锁当成仓库锁。目录也可能出现在状态中，但不能作为锁目标，预检会拒绝。
- 工作区、选择代际、状态令牌、完整路径集合、操作、说明、本地 SHA-256、属性、BASE/仓库身份及服务器锁状态均绑定计划。计划 120 秒一次有效，过期或任何失败都会消费确认；网页不能修改已预检的动作或路径。
- 刷新、切换工作区、修改选择或说明、关闭窗口使 UI 确认失效。执行前再次核对本地内容/元数据、服务器锁状态，并在最终命令前重查本地范围。其他写流程会使锁计划失效。
- 拒绝 added/deleted/replaced/missing/copied/moved/conflicted、外部引用、switched、管理锁、目录、链接、hardlink、reparse point、跨设备、嵌套工作副本、非法路径和不安全父目录。文件必须真实存在。
- 每文件 32 MiB、每遍选区 64 MiB 内容摘要上限，沿用每遍累计 10 秒协作式检查；每个严格 info 最多 256 KiB，属性单文件 256 KiB/总 4 MiB，状态最多 50,000 项。锁阶段设 90 秒协作式预算、单次原生命令最多 25 秒；不能强行中断被阻塞的文件系统调用，也不是原子化隔离。
- info 采用配套严格有界 XML 读取，任何 stderr、DOCTYPE/ENTITY、NUL、错误文件身份、重复关键身份/令牌字段都拒绝。不猜测本地化诊断是否无害。锁命令继续使用原版参数数组、Windows 消息/targets 处理和超时语义；没有 shell、任意参数或任意路径入口。
- 页面只收到精确路径、状态、布尔归属和字符串修订。原始锁令牌、仓库 URL/UUID、服务器自由文本及原始 stdout/stderr 不进入页面或操作日志。锁说明仅保留在进程中的短期计划，执行后不作为结果回显。

## 完成、失败与关闭

- 锁命令后再次读取服务器与本地令牌，只有整个明确选区达到预期才报告「已核实锁定/解锁完成」。零退出码本身不足以成功。
- 命令异常、部分完成、超时或后续服务器读取失败都显示结果未知，不自动重试或回滚。原始错误不会显示。成功且所有目标验证通过，但 stderr 有额外诊断时保留完成事实并显示警告。
- 已核实的完成结果不会被后续本地状态读取失败抹掉。清空旧状态、撤销能力，保留独立结果提示，要求显式刷新。
- 关闭执行窗口不取消已发送命令。迟到的已核实结果仍保留，但不会采用过时状态或自动重新打开窗口。
- 结果未知时清空行并禁用新锁操作。用户须先用可信原客户端检查仓库锁/本地令牌，成功明确刷新后确认已检查，才能重新审查；这不是自动重试按钮。其他浏览器会话也必须重新通过后端预检与一次确认。

## 验证与待验

合成临时文件和 mocked SVN 覆盖：双文件/特殊字符精确路径、干净文件、隐藏选区、锁归属、同用户其他副本、过期令牌、落后修订、内容等长修改恢复 mtime、属性/BASE 改变、执行前变化、计划过期/重放、部分写入/错误/诊断、读取失败、完成结果保留、禁用后端、身份隔离及 HTTP 鉴权/模式。

`npm test` 运行模型、实际控制器 DOM-adapter 与 Python 回归。DOM-adapter 不是浏览器执行验收。

```sh
npm test
python3 build-standalone.py
npm run test:locks:ui
```

浏览器脚本采用合成 HTTP 路由，不访问真实 SVN。当前环境 Playwright 所需 bundled Chromium 不在安装路径；现有系统 Chromium 启动在 `process_singleton_posix` 的 `socket()` 被权限限制阻止，未绕过。浏览器键盘默认行为、弹窗/菜单布局、CSP 实际执行、Windows WebView2/Tauri、真实 SVN / `svnadmin` 均未验。

Windows 下一轮仅使用可丢弃测试仓库：测试两工作副本加锁/解锁拒绝、`svn:needs-lock` 权限、中文/空格/@ 名称、一次确认/过期/关闭、锁被外部改变、网络中断和成功后状态读失败。不得在真实工作资料上做故障注入。配套旧提交/归组/Shelf 的历史待验事项仍然保留。
