# Windows 试用前：保留已完成操作的事实

基线 `2a25d94eee7fa918e8db9b04947ea8ada5bbe925`。本轮不增加工作流，不修改
原版后端、Shelf 格式、桌面壳或打包脚本，只修正跨流程的结果保留缺陷。

## 已复现并修正

- Shelf 已创建／恢复且服务已经验证完成后，后续状态读取失败或工作区候选失效，
  原桥接会丢失完成结果、只返回 `MutationUncertain`。现在保留 `shelfResult`，
  另行标记 `statusRefreshed:false`，返回空行／空令牌，撤销所有读写能力并提示刷新。
  只有原 Shelf 服务成功返回后才产生 verified 完成结果；服务报错仍是未知。
- 关闭正在执行的 Shelf 窗口后，原 UI 在校验服务响应之前丢弃迟到结果。现在用
  发起操作时保存的工作区、名称、备份 ID 和完整文件范围校验结果，保留已完成事实，
  同时不采用旧工作区的文件列表，不重新打开窗口。
- 提交、仓库锁和添加在拿到有效完成结果后，后续状态采用／渲染异常可能覆盖或
  丢失事实。现在先保存结果到独立持久提示，再更新状态；二次错误渲染失败也不
  抹掉已验证结果。提交修订仍只是 SVN 报告，未伪称独立服务器核查。
- 已核实锁操作不会因为单纯渲染失败被改成未知仓库结果。真正未知的锁结果仍
  要求用可信客户端核对，再明确刷新；绝不自动重试、force、回滚或扩大范围。

Shelf 完成响应新增 `statusRefreshed`，`shelfResult` 包含 `outcome:"verified"`、
`verified:true` 和限定警告码列表。前端严格校验这份契约，不接收旧版不完整响应；
更新时须同步替换服务、Web 资源并重启，不能混搭旧服务和新页面。

## 回归范围

新增整页脚本测试加载实际 `app.js`，从 `index.html` 建立 DOM adapter，并运行
实际选择、搜索、关闭、刷新及所有操作事件。覆盖隐藏选区、预检过期、双击确认、
六类写流程的迟到响应、Shelf 整体恢复、锁／解锁、移动／复制、完整 changelist
提交、验证后渲染失败和严格 capability 采用。它不是浏览器视觉或 WebView2 验收。

Python 回归包含所有写入口的鉴权／请求体矩阵、线程间互斥、候选替换和已完成
Shelf 的状态失败；并使用原版 Shelf 核心配合合成 XML 与临时文件创建／恢复备份，
验证结果保留且不可重放。本轮不调用真实 SVN，不访问用户实际工作副本。

Windows 真实 SVN、WebView2、安装／关闭生命周期和原生打包必须针对最终整合包
另行验收。已知 Chromium 启动权限限制未重试或绕过。
